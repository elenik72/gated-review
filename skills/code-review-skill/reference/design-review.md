# Design review — style guide, architecture and code design by the repo's own rules

> Режим `design` (`finding.py init --mode design`). Цель — не вкус ревьюера, а правила, которые команда
> уже записала, и соседи, которые уже так делают. Механика сверена 2026-09-30: правила из файлов репо
> с цитатой (Codex «Repository Rule Attribution», Claude code-review «quote the exact rule»), подавление
> стиля, которым владеет линтер (PR-Agent, Claude, Uber uReview), лимит nit (Claude REVIEW.md).

## 1. Откуда правило — первый источник выигрывает

1. **Конфиги репо** — `eslint.config.*`, `ruff`/`[tool.ruff]`, Prettier, `.editorconfig`, `tsconfig`,
   `import-linter`, `dependency-cruiser`. Действующее правило для файла — `eslint --print-config <file>`,
   `ruff check --show-settings <file>`. Всё, чем владеет форматтер или линтер, **не комментируется
   руками**; правило выключено в конфиге — это решение команды, не находка.
2. **Документы репо** — список печатает `finding.py init` («Правила репо»): `AGENTS.md` (раздел
   `## Code Review Rules` читают и Codex, и этот скилл), `CLAUDE.md`, `REVIEW.md`, `CONTRIBUTING.md`,
   `docs/**` про стиль, конвенции, архитектуру, ADR.
3. **Названный сосед** `path:line` — форма `drift`, когда правило не записано, но соседи единообразны.
4. **Публичные руководства** (PEP 8 / Google Python Style, Rules of React, Google TS Style) — только как
   обоснование. Правилом они становятся, лишь если на них ссылаются пункты 1–2.

## 2. Находка по правилу — форма `rule`

```bash
python3 <skill>/scripts/finding.py add --form rule --severity important --rung 1 \
  --claim "сервис импортирует роутер" \
  --breaks-when "app/services/pay.py:3 импортирует app.api -> цикл импортов при добавлении роутера платежей" \
  --location app/services/pay.py:3 --rule AGENTS.md:14-15
```

Скрипт читает указанные строки и цитирует их в комментарии; несуществующий файл, пустые строки или
чужой диапазон — отказ. «Так не принято» без строки правила — это `drift` с соседом или вопрос автору.

## 3. Архитектура: направление зависимостей

- **Есть контракт** (`import-linter`, `dependency-cruiser`, `eslint-plugin-boundaries`,
  `import-x/no-restricted-paths`) → его прогон — ступень 2, нарушение — факт (`breaks` с выводом).
  Диф ослабляет сам контракт или добавляет исключение — отдельная находка: правило ослабили молча.
- **Контракта нет** → не выдумывать. Грепнуть направление импортов (низ импортирует верх, домен знает
  фреймворк) и оформить как `drift` с двумя названными соседями. Предложить контракт можно как 💡.
- Типичные слои: бэкенд `api → services → repositories → models`; фронтенд `app → features → shared`,
  `shared` не импортирует `features`.

## 4. Дизайн кода — что стоит комментария

Только то, у чего есть цена в будущем и названный пример, — шаблоны в
[code-quality-universal.md](code-quality-universal.md) и [architecture-review-guide.md](architecture-review-guide.md):

- **Одна ответственность** — модуль/хук/сервис делает две вещи, и вторая уже нужна в другом месте (назвать где).
- **Язык предметной области** — имена расходятся с тикетом и глоссарием (`order` в коде, «заявка» в требованиях) — назвать оба места.
- **Уровень абстракции** — параметр, флаг или интерфейс «на будущее», у которого один вызов: цена — чтение и тесты сейчас.
- **Политика ошибок** — новый код обрабатывает ошибки иначе, чем соседи (глушит, пишет в другой лог, возвращает `null` вместо исключения).
- **Дублирование существующего** — `git grep` нашёл утилиту/хук/компонент, который уже это делает.

## 5. Шум

- В MR не больше 5 nit; остальное — `finding.py` оставит в REVIEW-NOTES с пометкой.
- Со второго раунда ревью (после правок автора) новые nit не постить: они размывают то, что осталось важным.
- Грейд по умолчанию: отход от соседей 🟢, нарушение записанного правила 🟡, нарушение контракта слоёв 🟡 (🔴 — если ломает сборку или вводит цикл).
